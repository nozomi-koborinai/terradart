# TerraDart Context

TerraDart defines Dart-first infrastructure code that synthesizes Terraform JSON. This glossary captures project-specific language used when discussing its generation and curated Google Cloud surface.

## Language

**Curated factory**:
A reviewed Dart wrapper shipped by `terradart_google` (GA), `terradart_google_beta` (beta-only types), or another provider package for a selected Terraform resource or data source. It is generated by the maintainer pipeline and committed for users to import directly.
_Avoid_: Generated binding, raw binding

**Beta-only factory**:
A curated factory for a `google_*` type present in `hashicorp/google-beta` and absent from the GA `hashicorp/google` schema. Shipped by `terradart_google_beta`; wrappers pin the `google-beta` provider meta-argument. Types that also exist in GA stay in `terradart_google`.
_Avoid_: Beta twin of a GA factory, overlapping GA type

**Maintainer generation pipeline**:
The release-time workflow that regenerates curated factories for `terradart_google`. It is optimized for the maintainer's ability to review, test, and publish a stable curated surface.
_Avoid_: User codegen, runtime synth

**User codegen** (removed):
A former external-user workflow (`terradart codegen`) for generating bindings outside the curated surface. Removed in favor of curation requests; users import `terradart_google` only.
_Avoid_: Maintainer generation pipeline

**Wrapper override**:
A TerraDart-owned file that records human API decisions for a curated factory after machine-readable schema data has been interpreted. It should not duplicate facts that can be derived from provider schema or Magic Modules metadata.
_Avoid_: Resource definition, MM YAML

**Merged IR**:
The generator's internal resource model after Terraform provider schema has been enriched with schema-gated Magic Modules metadata. It is the machine-readable source for wrapper emission.
_Avoid_: Wrapper override, schema.json

**Agent guide**:
Committed operational guidance that cloud and local agents can rely on without access to private notes. In this repository, `AGENTS.md` is the agent guide.
_Avoid_: Local notes, chat transcript dump

**Local notes**:
Gitignored working notes, historical design drafts, raw transcripts, and private planning under `docs/`. They can inform future work but are not authoritative for cloud agents.
_Avoid_: Agent guide, public docs

**Wave**:
A user-visible release batch of related curated factories. With the GA catalog filled, Waves originate from new resources the weekly schema bump detects and appends to the curation backlog.
_Avoid_: Sprint, milestone

**Migration manifest**:
The generated `packages/terradart_migrate/lib/src/manifest/<registry>.g.dart` (`terradart wrap --migrate-manifest`) that records, per curated factory, how each constructor slot, helper field, enum and output getter maps back to Terraform — the machine-readable recipe the HCL → Dart migrator follows. Derived from the wrapper inputs and emitted source; a shape it cannot derive is `manual` with a reason, gated by `lint-override` and `tool/migrate_manifest_debt.yaml`.
_Avoid_: Mapping table, conversion config

**Resource-atomic translation**:
The migrator's rule that a resource moves to Dart only when every argument of it translates; one untranslatable argument keeps the whole block in Terraform, listed in the report with the reason.
_Avoid_: Best-effort conversion, partial migration

**Leftover sidecar**:
The Terraform files the migrator writes next to `main.tf.json` — `terradart_leftover.tf`, plus `backend.tf` / `variables.tf` / `locals.tf` / `outputs.tf` — holding, verbatim and with a reason each, every block it did not translate (Terraform merges every file in the directory). Nothing is dropped silently, and nothing the Stack owns (its `required_providers`, provider configurations, backend, translated variables) is repeated.
_Avoid_: Fallback file, TODO file

**Child-module mode**:
The migrator's Stack output for a directory a `module` block's `source` points at: providers registered without configuration (synth emits only `required_providers`), `variable` → `addVariable`, `output` → exports; provider configurations and a backend found there stay in the sidecar. The caller's `module` block stays in its own sidecar, so plan addresses keep the `module.<name>.` prefix.
_Avoid_: Nested Stack

**Environment root**:
A root module directory with its own backend and state (`envs/dev`). Sibling roots under one parent directory are environment candidates; the migrator gives each its own Stack and Terraform directory and reports their shared addresses and differing arguments (`--merge-envs`, #668, folds them later).
_Avoid_: Workspace

**Round-trip gate**:
`tool/migrate_roundtrip_gates.dart`: migrate every quickstart's synth output back to Dart, re-synthesize, deep-compare — `synth(migrate(synth(S))) == synth(S)`. The migrator's correctness oracle; strict examples must round-trip completely, `tool/migrate_roundtrip_debt.yaml` ratchets the reasoned exceptions.
_Avoid_: Golden diff

**Zero-diff plan**:
The migrator's acceptance criterion: after migrating a module, `terraform plan` against the existing state reports *No changes*. Resource addresses are always preserved.
_Avoid_: Best effort, approximately equivalent

**Debt ledger**:
A machine-checked YAML under `tool/` (for example `example_debt.yaml`, the apply-smoke skip lists, `apply_cost_denylist.yaml`, `migrate_roundtrip_debt.yaml`) that records a reviewed, reasoned gap so CI can enforce that every gap is a decision, not an accident.
_Avoid_: TODO list, wishlist

**Apply-excluded path**:
Curating a factory whose example coverage is synth + `terraform validate` only, with the real-apply gap recorded in a debt ledger. Used heavily in the 2026-08 GA-catalog fill; paying the debt down is standing maintenance-phase work.
_Avoid_: Untested, uncovered

## Example Dialogue

Dev: "Should users run codegen for Pub/Sub?"

Maintainer: "No. Pub/Sub is a curated factory, so users import `terradart_google/pubsub.dart`. The maintainer generation pipeline regenerates that factory before release."

Dev: "Where do enum hints from Magic Modules go?"

Maintainer: "They enrich the merged IR. A wrapper override only remains when we make a human API decision, such as adding a convenience getter or shaping a sealed helper type."

Dev: "Can an agent rely on my local notes?"

Maintainer: "No. Agents should rely on `AGENTS.md`, `CONTEXT.md`, checked-in tooling, and CI. Local notes are private working material and only become authoritative after being distilled into committed guidance or public docs."
